## 2. 日常使用：换应用后执行一条命令

1. 将需要分析的应用源码放到项目根目录的 `php-app/` 中。更换应用时，先移走上一应用，避免混入旧源码。保留新应用内部的目录、包含文件和依赖布局。
2. 在终端进入项目根目录，执行：

```bash
cd /home/z/桌面/XSS
./prepare_step7.sh
```

3. 只有最后写入 Apache 目录时可能提示 sudo 密码。**请以普通用户启动入口，不要执行 `sudo ./prepare_step7.sh`。**
4. 看到以下提示后，说明已准备好进入步骤 7：

```text
已部署 ... 个 PUT：/var/www/html/php-app
步骤 1–6 已通过：... 个 PUT。
已到达步骤 7 入口；PUT_fuzzer 尚未运行。
```

日常无需再手动复制 CSV、清空 `/opt/neo4j` 数据库、复制完整数据库安装、填写污点节点编号或复制 PUT。

入口可从其他工作目录调用；默认分析目录始终是该项目下的 `php-app/`。

## 3. 自动流程具体做什么

| 阶段 | 自动操作 |
| --- | --- |
| 环境检查 | 检查 PHP、Java 11、Python 提取器依赖、Neo4j 模板、已有认证配置和应用源码 |
| 步骤 1 | 保存源码快照，使用 phpjoern 生成 AST CSV，检查解析器错误 |
| 步骤 2 | 执行 TChecker，保存完整日志，解析末尾完整的路径 JSON |
| 步骤 3 | 转换 CSV，检查列数、重复节点、记录数量及路径引用；导入全新数据库 |
| 步骤 4 | 启动独立且需要认证的本地 Neo4j，查询核对节点和关系数量 |
| 步骤 5 | 将本次路径写入本批次提取器的 `storage/taint_flows/php-app.json` |
| 步骤 6 | 提取 PUT，核对数量和必要文件 |
| 发布与部署 | 备份并更新共享 PUT 和路径文件，部署到 Web 目录，保留上一部署备份 |

每个批次使用独立的 Neo4j 数据目录和空闲本地端口。流程结束时关闭该实例。脚本不会清空 `/opt/neo4j/data`，也不依赖之前数据库里是否已有旧应用。

Neo4j 导入保留字符串类型的节点 ID，以兼容当前提取器中按字符串 ID 查询的 Cypher，避免源变量适配或调用点查询悄悄失效。

## 4. 常用命令

### 仅检查依赖

```bash
./prepare_step7.sh --check-only
```

该命令成功只表示依赖检查通过，不等于已经执行过步骤 1～6。

### 完成步骤 1～6，暂不部署

```bash
./prepare_step7.sh --skip-deploy
```

会更新共享 PUT 和污点路径文件，但不会更新 `/var/www/html/php-app`。此时不要把旧 Web 目录当成本次结果来跑 fuzzer。

### 将已经准备好的批次部署到 Apache

将下面的路径替换为终端打印的本批次目录：

```bash
./prepare_step7.sh --deploy-only runs/preparation/20261123-153932-363066
```

这样无需重新跑静态分析和提取。部署失败后也可用此命令继续，前提是该批次的 `manifest.json` 中 `status` 为 `prepared`。

### 指定其他源码目录

```bash
./prepare_step7.sh --app /绝对路径/其他PHP应用
```

输出与部署的项目名称仍为 `php-app`。默认发布会替换共享 `php-app` 结果，不用于并发维护多个应用。

### 验证其他应用且保留当前共享结果

```bash
./prepare_step7.sh --app /绝对路径/其他PHP应用 --skip-deploy --no-publish
```

新结果保存在本批次目录中；不会更新共享 PUT 或路径文件。

### 自定义已有 Web 根目录

```bash
./prepare_step7.sh --web-root /其他/已有Web根目录
```

该目录必须事先存在，部署子目录固定为 `php-app`。用于步骤 7 时，还需要 Apache 的实际 URL 映射与 fuzzer 配置相符；单纯复制到普通目录不代表 Apache 已能访问它。

### 调整解释器、Java 或内存

```bash
PYTHON=python ./prepare_step7.sh
PHP7=/usr/bin/php ./prepare_step7.sh
./prepare_step7.sh --java-home /usr/lib/jvm/java-11-openjdk-amd64
./prepare_step7.sh --java-heap 4G --timeout 3600
./prepare_step7.sh --neo4j-home /opt/neo4j
```

`--java-heap` 默认 `2G`，用于 TChecker；`--timeout` 默认 1800 秒，作用于单个分析命令。独立 Neo4j 的堆上限为 512 MB，页缓存为 256 MB。

环境应使用已安装本项目依赖的 Python。脚本复用已有 `config/neo4j.json` 中 `php-app` 的认证信息及已有 `auth.ini`，不会替你安装依赖或初始化一个全新的环境。认证不匹配时需要修正这两处配置。

## 5. 进入步骤 7

确认本次已经部署成功，且 Apache 和现有 PHP 插桩环境正常，然后手动运行：

```bash
cd /home/z/桌面/XSS/llm-xss/PUT_fuzzer
python PUT_fuzzer.py --test_path /var/www/html/ --output output/php-app.json
```

这里的 `--test_path` 是包含 `php-app` 的父目录。当前 fuzzer 会扫描其下的项目目录，因此该父目录中如果还部署了其他项目，也可能被一并处理。

需要大模型增强时，可在原有配置基础上添加参数：

```bash
python PUT_fuzzer.py \
  --test_path /var/www/html/ \
  --output output/php-app.json \
  --enable_llm \
  --llm_provider deepseek \
  --llm_api_key "$DEEPSEEK_API_KEY" \
  --llm_model "你实际使用的模型名称"
```

执行前自行设置 `DEEPSEEK_API_KEY`。准备脚本不需要该密钥，手册也不保存密钥。

每次执行都会打印独立目录：

```text
├── cpg/                         # 原始 AST、CPG CSV

├── taint-flows.json              # 本批次静态候选路径
├── neo4j/                       # 本批次数据库、配置及数据库日志
├── extractor/                   # 本批次提取器与生成的 PUT
├── 01-phpjoern.log
├── 02-tchecker.log
├── 03-csv.log
├── 03-import.log
├── 04-start.log
├── 04-stop.log
├── 06-extractor.log
├── deployment.json              # 部署成功后生成，记录目标目录及旧部署备份

```

成功发布后，常用共享产物仍在：

```text
llm-xss/PUT_extractor/storage/taint_flows/php-app.json
llm-xss/PUT_extractor/storage/PUT/php-app/
```

共享产物对应最近一次成功发布的批次。发布时原样保留所有生成的 PUT，包括有 PHP 语法错误的文件。使用 `--no-publish` 时只保存批次产物。

建议论文实验记录同时保存源码快照、`manifest.json`、静态路径及步骤 7 的结果文件。PUT 编号是本次路径序号，不能假定不同应用或不同批次的同一编号表示同一漏洞。

每批次保留一份 Neo4j 运行环境和数据库，会占用磁盘。确认不再需要复现实验或恢复旧结果后，再自行归档或清理对应批次。

## 7. 失败处理与边界

| 现象 | 含义及处理 |
| --- | --- |
| 退出码 `0` | 所选操作成功；`--skip-deploy` 或 `--check-only` 的成功不表示已经部署 |
| 退出码 `1` | 依赖、分析、提取、校验或部署失败；查看终端及批次日志 |
| 退出码 `3` | TChecker 没有报告路径，停止准备；不代表应用已证明安全 |
| sudo 提示需要密码 | 在自己的交互终端输入系统密码；不要以 root 重跑整个准备流程 |
| 另一流程正在运行 | 等待原流程完成；脚本使用文件锁防止共享产物被并发替换 |
| Neo4j 90 秒内未就绪 | 查看 `neo4j/logs/`，检查认证配置、Java 及内存 |
| PHP 解析器报错 | 查看 `01-phpjoern.log`，确认源码语法及当前 PHP/AST 扩展能否解析它 |

无候选路径或失败时，旧部署可能仍然存在。**请勿在本次准备未成功时直接运行步骤 7，否则可能测试到旧应用。** `manifest.json` 的 `prepared` 只表示步骤 1～6 通过；部署是否成功还要看 `deployment.json` 和终端提示。

整合脚本不要求 PUT 包含 GET 入口，也不根据输入来源判断其是否适用于后续测试。它负责执行准备和部署步骤；具体测试结果由步骤 7 判断。

PHP 7 的 AST 解析器不保证兼容任意新版 PHP 语法；TChecker 保留其原有目录及分析规则，部分 `test`、`Test`、`vendor` 等路径可能受到特殊处理。提取器包含变量占位和函数替代逻辑，论文结论应结合原源码及步骤 7 的实际结果复核。
