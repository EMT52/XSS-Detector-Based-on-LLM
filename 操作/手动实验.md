# 在容器终端逐条运行实验

宿主机先把待测源码放到 `php-app/`，然后进入环境：

```bash
./进入环境.sh --pull
```

首次拉取已发布的镜像，以后只需 `./进入环境.sh`。进入后是普通 Bash，
`cd`、`python`、`php`、`java`、编辑脚本和运行自己的测试命令都可以直接使用。
启动环境只初始化运行依赖和 Apache，不自动分析应用或运行 fuzzer。
容器中的 `/workspace/XSS` 对应宿主机整个项目目录，修改和输出实时保留。
Windows 从 Docker Desktop 已启用集成的 WSL 终端使用相同入口。

以下步骤在这个 Bash 中逐条执行。每步可以停下来检查 CSV、日志、数据库和 PHP。
这些手动步骤会更新共享中间文件和部署，请勿与自动准备流程同时执行。

## 1. PHP 转 AST

```bash
cd "$XSS_ROOT/phpjoern"
./php2ast "$XSS_ROOT/php-app"
```

输出为当前目录的 `nodes.csv`、`rels.csv`。
想先试示例，可将应用路径换成 `"$XSS_ROOT/examples/demo-app"`；
下一步 TChecker 的应用路径也要同时替换。

## 2. TChecker 静态分析

```bash
cp "$XSS_ROOT/phpjoern/nodes.csv" "$XSS_ROOT/TChecker/"
cp "$XSS_ROOT/phpjoern/rels.csv" "$XSS_ROOT/TChecker/"
cd "$XSS_ROOT/TChecker"
java -Xmx2G -cp 'bin:lib/*:ApacheCommons/commons-cli-1.4/*:ApacheCommons/commons-csv-1.8-bin/commons-csv-1.8/*:ApacheCommons/commons-lang3-3.10/*:ApacheCommons/*' \
  tools.php.ast2cpg.Main "$XSS_ROOT/php-app" \
  | tee "$XSS_ROOT/.docker-state/manual-tchecker.log"
```

查看日志末尾的候选路径数组，以及当前目录中的 `cpg_edges.csv`。
应用绝对路径不要含 `test`，避免原 TChecker 的路径过滤。
修改 Java 源码后，先执行普通命令 `xss rebuild`，也可以自行运行 `javac`。

## 3. 转换 CSV

```bash
cd "$XSS_ROOT/neo4j-import-data"
cp "$XSS_ROOT/TChecker/nodes.csv" .
cp "$XSS_ROOT/TChecker/rels.csv" .
cp "$XSS_ROOT/TChecker/cpg_edges.csv" .
python fix_csv_for_neo4j_admin.py
```

检查 `wordpress_fixed/` 的转换结果及错误计数；出现错误时先处理，不继续导入。

## 4. 准备独立数据库并导入

以下命令备份已有手动数据库，再从容器内的空模板创建一份数据库。
不需要 `sudo`，连接使用 `localhost:7474`、用户名 `neo4j`、密码 `1`。
旧数据库备份会占磁盘，可在确认不需要后自行清理。

```bash
cd "$XSS_ROOT/llm-xss/PUT_extractor"
stamp=$(date +%Y%m%d-%H%M%S)
mkdir -p "$XSS_ROOT/.docker-state/manual-backups" databases config
if [ -d databases/php-app ]; then
  databases/php-app/bin/neo4j stop || true
  mv databases/php-app "$XSS_ROOT/.docker-state/manual-backups/db-$stamp"
fi
if [ -f config/neo4j.json ]; then
  cp -p config/neo4j.json "$XSS_ROOT/.docker-state/manual-backups/config-$stamp.json"
fi
cp -a /opt/neo4j databases/php-app
cp "$XSS_NEO4J_CONFIG" config/neo4j.json
printf '\ndbms.memory.heap.initial_size=256m\ndbms.memory.heap.max_size=512m\ndbms.memory.pagecache.size=256m\n' >> databases/php-app/conf/neo4j.conf
databases/php-app/bin/neo4j-admin import \
  --database=neo4j --id-type=STRING --delimiter=TAB --quote='"' \
  --multiline-fields=true \
  --nodes="$XSS_ROOT/neo4j-import-data/wordpress_fixed/nodes.csv" \
  --relationships="$XSS_ROOT/neo4j-import-data/wordpress_fixed/rels.csv" \
  --relationships="$XSS_ROOT/neo4j-import-data/wordpress_fixed/cpg_edges.csv"
```

## 5. 保存本次候选路径

可以照原流程手动把 TChecker 末尾数组保存到
`storage/taint_flows/php-app.json`，也可以单独执行下面这一步解析本次日志：

```bash
cd "$XSS_ROOT"
python - <<'PY'
import json
from pathlib import Path
from scripts.prepare_step7 import read_paths
paths = read_paths(Path('.docker-state/manual-tchecker.log').read_text())
target = Path('llm-xss/PUT_extractor/storage/taint_flows/php-app.json')
target.parent.mkdir(parents=True, exist_ok=True)
target.write_text(json.dumps(paths, indent=2))
print(paths)
PY
```

没有候选路径时，本次无 PUT；不要拿上一应用的 PUT 继续测试。

## 6. 生成 PUT

```bash
cd "$XSS_ROOT/llm-xss/PUT_extractor"
if [ -d storage/PUT/php-app ]; then
  mv storage/PUT/php-app "$XSS_ROOT/.docker-state/manual-backups/put-$stamp"
fi
python PUT_extractor.py --target=php-app
```

该原始入口会启动数据库、提取 PUT，最后关闭数据库。
检查终端日志和 `storage/PUT/php-app/`；这个旧入口不保证失败时返回非零退出码。
可逐个执行 `php -l 文件路径` 检查生成文件。

## 7. 部署后运行自己的测试命令

```bash
if [ -d "$XSS_WEB_ROOT/php-app" ]; then
  mv "$XSS_WEB_ROOT/php-app" "$XSS_ROOT/.docker-state/manual-backups/web-$stamp"
fi
cp -a "$XSS_ROOT/llm-xss/PUT_extractor/storage/PUT/php-app" "$XSS_WEB_ROOT/"
cd "$XSS_ROOT/llm-xss/PUT_fuzzer"
python PUT_fuzzer.py --output output/php-app.json
```

`XSS_WEB_ROOT` 已设置好，所以默认路径无需再输入。也可以自行指定 `--test_path`，
或直接运行自写的 Python/PHP 测试。浏览器从容器内部访问 `http://localhost/`，
宿主机通过 `http://localhost:8080/` 查看部署。
启用 LLM 时，在本机 `.env` 设置 Key 后重建容器，再给命令追加提供商和模型参数。
默认 PHP 为普通版本，sanitizer 插桩反馈尚未验证；详见 Docker 使用说明。

运行 `exit` 离开 Bash，后台环境继续运行。宿主机执行 `docker compose down`
停止环境，挂载的代码和输出仍保留。

需要自动准备时，可在项目根目录自行执行 `./prepare_step7.sh`；
这只是可选脚本，进入容器不要求使用它。
